# kuma_health

增加独立 NoneBot 插件，通过 `KUMA_PUSH_URL` 向已有 Uptime Kuma Push
监控上报 Kasumi 的实际状态。不配置或配置为空时关闭后台任务。

## 实现方式

采用应用生命周期内的异步任务，复用现有 HTTPX 与 QQ 适配器，不引入调度器。
仅检查在线机器人列表会误判尚未收到事件的 Webhook 账号，因此主动检查配置中的账号。
单纯按进程存活发送心跳不能满足真实状态检查要求。

- 启动后等待 60 秒，之后按每轮开始时间间隔 60 秒检查，避免监听端口尚未就绪。
- 向本机 `/qq/webhook` 发送 QQ 验证请求，检查成功响应及验证内容，确认应用可响应。
- 使用适配器的 `Bot.me()` 主动调用 QQ `/users/@me`，所有已配置账号均成功且身份 ID
  非空时才算健康；探测机器人复用访问令牌，不依赖已收到 QQ 事件。
- 无 QQ 配置、Webhook 或身份检查失败、超时、异常响应均上报 `down`；全部通过上报 `up`。
- 每次 HTTP 请求及每个身份检查限时 10 秒；Kuma 上报失败只记录异常类型并继续下一轮。
- 合并 URL 查询参数，覆盖原有 `status`、`msg`、`ping`，保留其他参数，不记录含令牌的 URL。
- 在当前上报上下文屏蔽 HTTPX 的 URL 日志，防止 INFO 日志泄露 Push 令牌。
- 并发检查所有 QQ 账号，并等待每项结束或超时后再上报，不遗留其他账号的后台探测。
- 应用退出时取消并等待后台任务，关闭 HTTP 客户端。

不创建 Kuma 监控，不改变 QQ 消息处理。按用户后续指令提交并推送 `main`。
